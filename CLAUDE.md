# stock_dw
Point-in-time stock data warehouse. Portfolio project. Design: DESIGN.md.

## How to work
- Keep answers short. No jargon. No long or repeated explanations.
- Stay on the user's topic. Don't suggest next steps or offer to do things unasked.
- Don't summarize after every action.
- Write minimal code. Don't comment everything.
- Add logging like a human would: key steps, counts, errors.
- Avoid touching code unless needed.
- Keep the number of files small. Only split a file when it gets too big to read.
- Implement incrementally.
- Don't write lots of tests or rerun tests after every change.
- No unnecessary commands. Never commit or push; the user does that.
